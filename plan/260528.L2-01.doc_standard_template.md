# L2-01 文件標準架構最小調整方案

- **分析目標**：使 `doc/L2-01_vulnerability-handling-and-disclosure-process.md` 符合 `template/文件管制程序2.7.doc` 第 6.4.2 所列二階文件架構。
- **輸出性質**：master context engineer 分析與修改方案；本文件不直接取代 L2 程序書。
- **目標文件**：`doc/L2-01_vulnerability-handling-and-disclosure-process.md`

## 1. 背景與目標

`template/文件管制程序2.7.doc` 第 6.4.2 指定文件架構應為：

1. 一、目的
2. 二、適用範圍
3. 三、組織與責任
4. 四、定義
5. 五、流程圖
6. 六、程序
7. 七、相關文件
8. 八、附件

現行 L2-01 已具備大部分內容，但章節順序與章節名稱不完全符合上述標準。最小調整目標是：不改變弱點處理與揭露程序的實質要求，只調整章節層級、章節歸屬與必要標題，使文件可對應公司二階文件標準架構。

## 3. 合理假設

1. 第 6.4.2 所列「一、二、三...」是文件架構要求，不一定要求在 Markdown 中使用中文大寫章節號；後續 DOCX 轉換仍可依既有 workflow 移除 Markdown heading 前置數字。
2. L2-01 作為 PSIRT 程序文件，仍需保留 ISO/IEC 29147、ISO/IEC 30111、CRA、SBOM/HBOM、Jira 留痕與稽核要求；調整僅限章節歸類與標題。
3. 「附件」可容納文件治理、修訂紀錄、下階文件清單與表單/模板清單；若公司文件管制程序另有強制附件格式，需由文件管制 owner 補充。
4. 若後續要產生 DOCX，必須依 `prompt/workflow/markdown_convert_msword.md` 與 `build/` 執行，不應在本 plan 中另行指定 Word 樣式。

## 4. 風險判斷

| 影響面 | 風險 | 判斷 |
|---|---|---|
| 標準符合性 | 若維持 13 個主章節，可能不符合文件管制程序 6.4.2 的二階文件章節架構 | 應收斂為 8 個主章節 |
| 內容遺漏 | 若單純刪除 `程序原則`、`對外溝通政策`、`Jira 記錄`、`稽核` 等章節，會失去 PSIRT 核心控制要求 | 應採搬移與降階，不採刪除 |
| 稽核可讀性 | 將所有內容塞入「程序」可能造成章節過長 | 可在第六章下保留清楚的二階/三階小節 |
| 文件轉換 | 若手工改 Word 而未同步 Markdown 與 workflow，會造成來源與 DOCX 不一致 | 後續 DOCX 必須由既有 markdown-to-MS-Word workflow 產出 |
| 翻譯完整性 | 新增或改標題會造成 translation memory 缺漏 | 修改 L2 後需同步補翻譯記憶庫 |

## 5. 建議採用的最小修改策略

不建議重寫程序內容。建議以「主章節重排、原內容降階」方式調整：

1. 保留現有內容文字，除章節標題與必要轉場句外，不改變政策含義。
2. 將主章節收斂為 8 個：
   - `1. 目的 Purpose`
   - `2. 適用範圍 Applicable Scope`
   - `3. 組織與責任 Organization and Responsibility`
   - `4. 定義 Definitions`
   - `5. 流程圖 Flow Chart`
   - `6. 程序 Procedure`
   - `7. 相關文件 Related Documents`
   - `8. 附件 Attachments`
3. 原 `3. 程序原則` 與 `3.1 準備能力` 搬入 `6. 程序` 下，作為 `6.1 程序原則` 與 `6.2 準備能力`。
4. 原 `7. 流程要求` 搬入 `6. 程序` 下，作為 `6.3 流程要求`，原 `7.1` 至 `7.10` 依序改為 `6.3.1` 至 `6.3.10`。
5. 原 `8. 對外溝通政策` 搬入 `6. 程序` 下，作為 `6.4 對外溝通政策`。
6. 原 `10. Jira 記錄與資料保護` 搬入 `6. 程序` 下，作為 `6.5 Jira 記錄與資料保護`。
7. 原 `11. 稽核與量測` 搬入 `6. 程序` 下，作為 `6.6 稽核與量測`。
8. 原 `5. 角色與利害關係人` 與 `9. 利害關係人管理` 合併至 `3. 組織與責任`；角色責任表保留在 `3.1`，利害關係人管理保留在 `3.2`。
9. 文件開頭 metadata 中的「相關文件」搬至第 7 章；開頭僅保留必要文件屬性或改由 Word 封面/文件控制表處理。
10. 原 `12. 文件治理與版控` 與 `13. 修訂紀錄` 搬入第 8 章附件，例如 `8.1 文件治理與版控`、`8.2 修訂紀錄`。

## 8. 不建議修改的內容

1. 不建議刪除 `程序原則` 與 `準備能力`；它們是支援 ISO/IEC 30111、prEN 40000-1-3、CRA 與供應鏈資安管理的重要程序控制。
2. 不建議刪除 `對外溝通政策`；它支援 ISO/IEC 29147 與 coordinated vulnerability disclosure。
3. 不建議刪除 `Jira 記錄與資料保護`；它支援可稽核性、CRA 留痕與個資/敏感資料保護。
4. 不建議刪除 `稽核與量測`；它是程序有效性與持續改善依據。
5. 不建議直接在 Word 中手工重排後不回寫 Markdown；正式來源應維持 Markdown 與 DOCX 轉換流程一致。

## 9. 對 workflow 與 translation memory 的影響

1. 若實際修改 L2 標題，需同步補 `prompt/translation/translation_memory_l2_01.json`，至少包含新標題：
   - `適用範圍 Applicable Scope`
   - `組織與責任 Organization and Responsibility`
   - `流程圖 Flow Chart`
   - `程序 Procedure`
   - `相關文件 Related Documents`
   - `附件 Attachments`
2. 後續 DOCX 產出必須依 `prompt/workflow/markdown_convert_msword.md` 執行，避免 MS Word 樣式、字級與文件管制格式被繞過。
3. 章節號調整後，需確認 `build/build_qp_docx.py` 的 heading number stripping、英文 numbered paragraph 移除數字規則與 Mermaid 圖片插入位置仍符合預期。

## 10. 最小修改結論

本次需求不需要重寫弱點處理流程。建議採取「八大主章節重排」作為最小修改：

1. 將現行 13 個主章節收斂為文件管制程序 6.4.2 指定的 8 個主章節。
2. 原有 PSIRT 程序控制內容全部保留，僅搬移至對應章節下。
3. `程序原則`、`準備能力`、`流程要求`、`對外溝通政策`、`Jira 記錄`、`稽核與量測` 均納入「六、程序」。
4. `文件治理與版控` 與 `修訂紀錄` 移至「八、附件」。
5. 實際改 L2 前，應先確認文件擁有者接受「附件」包含文件治理與修訂紀錄的處理方式。
